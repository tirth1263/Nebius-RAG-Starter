The problem

Language models are confident about things they were never taught.

Retrieval-Augmented Generation fixes that by looking up the right passage from your documents at question time and handing it to the model as context. The model's job shrinks from "recall a fact" to "read this and answer" — a task language models are dramatically better at.

📂

Any folder, any format

SimpleDirectoryReader ingests Markdown, text, PDF, DOCX and CSV from a local directory — no per-format code to write.

⚡

In-memory vector index

VectorStoreIndex builds the whole index in RAM. Zero infrastructure to stand up while you're still learning the shape of it.

☁️

Nebius-hosted models

Embeddings and generation run server-side on Nebius Token Factory. One API key, no local weights, no accelerator.

How it works

Four stages, start to finish

Load documents, embed them into vectors, retrieve the closest matches to a question, then let the LLM write an answer constrained by what was actually retrieved.

STAGE 01

Load

Walk the directory and parse every file into LlamaIndex Document objects.

STAGE 02

Index

Split into chunks, embed each one into a vector — a numeric fingerprint of its meaning — and store them.

STAGE 03

Retrieve

Embed the question with the same model, compare by cosine similarity, keep the closest k chunks.

STAGE 04

Generate

Pack those chunks into a prompt and let the LLM answer, constrained by what was actually retrieved.

The whole thing

This is the entire application

Not a simplified excerpt. The function below is what runs — everything else in the notebook is explanation around it.

nebius_rag.ipynb 
from llama_index.core import Settings, SimpleDirectoryReader, VectorStoreIndex
from llama_index.embeddings.nebius import NebiusEmbedding
from llama_index.llms.nebius import NebiusLLM


def run_rag_completion(
    document_dir: str,
    query_text: str,
    embedding_model: str = "BAAI/bge-en-icl",
    generative_model: str = "deepseek-ai/DeepSeek-V3",
    similarity_top_k: int = 5,
) -> str:
    # Point LlamaIndex at Nebius Token Factory
    Settings.llm = NebiusLLM(api_key=NEBIUS_API_KEY, model=generative_model)
    Settings.embed_model = NebiusEmbedding(api_key=NEBIUS_API_KEY, model_name=embedding_model)

    # 1. Load every document in the directory
    documents = SimpleDirectoryReader(document_dir).load_data()

    # 2. Chunk, embed and index them in memory
    index = VectorStoreIndex.from_documents(documents)

    # 3. Retrieve top-k chunks and generate a grounded answer
    response = index.as_query_engine(similarity_top_k=similarity_top_k).query(query_text)

    return str(response)
Ask a question
answer = run_rag_completion(
    document_dir="./data",
    query_text="What is RAG, and why use it
                 instead of fine-tuning?",
)
print(answer)
See where the answer came from
for node in response.source_nodes:
    print(node.metadata["file_name"],
          round(node.score, 4))
    print(node.get_content()[:200])

Quickstart

Sixty seconds to your first grounded answer

The repo ships with sample documents in ./data, so it answers a real question on the very first run — no setup ritual required.

1 · Install
# clone and install
git clone https://github.com/tirth1263/Nebius-RAG-Starter.git
cd Nebius-RAG-Starter
pip install -r requirements.txt
2 · Add your key
# get one at https://dub.sh/nebius
cp .env.example .env

# .env
NEBIUS_API_KEY="your_nebius_api_key"
3 · Run it
jupyter notebook nebius_rag.ipynb

# Point `document_dir` at your own folder, set `query_text`
# to your question, then run all cells.

🔒 .env is gitignored, and the notebook falls back to an interactive getpass prompt — your API key never has to be saved inside the .ipynb.

Where to go next

This is the floor, not the ceiling

Once the pipeline makes sense, these are the upgrades that pay off first — roughly in order of return on effort.

▸

Persist the index

index.storage_context.persist() so you stop re-embedding unchanged documents. Biggest cost win available.

▸

Add a reranker

Retrieve 20 candidates, rerank, keep the best 5. Vector similarity is a coarse signal.

▸

Hybrid search

Combine dense vectors with BM25 to catch exact terms that embeddings blur over.

▸

Move to a real vector store

Qdrant, Chroma or pgvector, once the collection outgrows RAM.

▸

Tune chunking

chunk_size and chunk_overlap affect answer quality more than most people expect.

▸

Stream the response

as_query_engine(streaming=True) for a UI that feels alive instead of frozen.
